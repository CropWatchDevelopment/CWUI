Getting started

Before you design your first screen

CropWatch is a sensor-monitoring platform for farms and greenhouses. Users check it on desktops in an office and on phones in the field, in daylight and at night, so every screen ships in a dark theme (the default) and a light theme. The UI library CWUI implements both from one set of design tokens.

How the system is organised

  1. Palette tokens are raw colours such as --cw-primary-500. They never change between themes.
  2. Semantic tokens describe a job, such as --cw-text-muted or --cw-tone-danger-text. Each theme maps them to a different palette value.
  3. Component tokens such as --cw-control-h-md or --cw-popover-bg hold the shared sizes and surfaces that keep components consistent.

Design with semantic tokens. If a mock-up uses a palette colour directly, it will look right in one theme and wrong in the other.

Your first week

  • Open the demo site and click through every component in both themes (moon/sun button, top right).
  • Set up two colour libraries in your design tool, CW Dark and CW Light, using the semantic names on pages 5 to 8. Name styles after the token, e.g. text/muted.
  • Install Inter and JetBrains Mono (page 10).
  • Build frames at 390, 768 and 1440 px wide (page 11).
  • Reuse an existing component before drawing a new one. The component list is on the demo home page.

Brand

Logo and brand colours

The mark is a bronze tree with a canopy of green leaves. The CropWatch green is used for the application header in light mode and as the company colour in print. The teal accent is the interactive colour inside the product.

  • Keep clear space around the mark of at least a quarter of its width on every side.
  • The side nav shows the mark at 24 px, and at 20 px in the collapsed icon rail. Do not use it smaller than 20 px.
  • Do not recolour, outline, stretch or rotate the mark, and do not place it on photographs.
  • Write the name as CropWatch: one word, capital C and W.

Colour · tones

Tones

Six tones carry meaning across chips, badges, toasts, buttons and alerts. Each tone has three styles: soft (tinted background, tone text), outline (border and tone text) and solid (filled, used sparingly for counts and the most urgent states).

Accent and focus

The accent is teal in dark mode and blue in light mode. Keyboard focus is always a solid 2 px ring in --cw-focus-ring-color with a 2 px gap. Draw it on every interactive element in your state sheets.

Colour · data visualisation

Chart colours

Charts use two colour sets. The categorical palette colours series that have no fixed meaning, in this order. Metric colours are fixed per measurement so temperature is red-toned and humidity is blue on every chart in the product.

Dark

Light

Metric colours

  • Never use status colours (success, danger) for categories. A red series reads as "alarm".
  • Temperature lines use a value gradient: cold values blue, hot values red.
  • Legends sit below the plot. Each legend item toggles its series; the last visible series cannot be hidden.
  • Axis and tick labels are 11 px with tabular (fixed-width) numerals so values line up.
  • Every chart needs a loading state and a "No data available" state.
Typography

Typography

Inter is the interface typeface. JetBrains Mono is used for device IDs (DevEUI), code and event logs. Both are free on Google Fonts.

Writing values

  • 23.4 kPa: a non-breaking space between value and unit.
  • 23.4°C, 65%: no space before °C, °F and %.
  • — for a missing value; never 0 or N/A.
  • Use the user's locale for dates and decimals (the app supports English and Japanese).

Writing labels

  • Sentence case everywhere: "Last seen", not "Last Seen".
  • Buttons are verbs: "Save changes", "Add device".
  • Use the ellipsis character "…" in placeholders, not three full stops.

Hand-off

Hand-off checklist

Go through this list before a design goes to development. Each item maps to a rule the component library already enforces, so a design that fails one will be changed in the build.

Every screen

  • Drawn in dark and light.
  • Drawn at phone and desktop widths.
  • Colours named by semantic token.
  • Text contrast checked: 7:1 body, 4.5:1 large text and icons.
  • No text smaller than 11 px.
  • Every status shown with a word or icon as well as colour.
  • Focus order and focus ring shown for interactive elements.

Every data view

  • Loading state (skeleton, not a blank area).
  • Empty state: "No data available" with a short reason.
  • Error state with what happened and what to do next.
  • Stale data: value dimmed plus "Last seen … ago".
  • Missing readings shown as "—".
  • Numbers right-aligned in tables, tabular numerals.
  • Units spaced per the typography page.
